Prepared only. Do not execute during A05's active quiet reservation. The coordinator must hold the full host/build reservation before passing the explicit execution flag. Product sources, Git, Java, Maven, Docker and product measurements were not changed or started during this preparation.

From /workspace/Java-portfolio, with approximately 20–22 minutes reserved plus cleanup margin:

```sh
python3 .work/A10/quiet-run.py --execute-quiet
```

Optional fresh output directory (must be inside .work/A10 and must not exist):

```sh
python3 .work/A10/quiet-run.py --execute-quiet --output .work/A10/quiet/reference-final-01
```

No Maven is invoked. The runner uses the already verified source d5964723… and exact service/driver JAR hashes in evidence/artifacts-current.json. It does not rebuild, download dependencies, pull a new browser, prune Docker or delete unrelated files. The pinned PostgreSQL image is already cached; the existing up script owns starting its single stack. Database reset is the existing demo-tenant-only endpoint and occurs before measurements. The earlier current-source demo/browser closure remains at evidence/lifecycle-current; it is not repeated or mixed into the measured corpus.

The default initial disk minimum is 4 GiB on /workspace and 256 MiB on /tmp. Root can select a different initial workspace threshold with --min-free-mib, minimum 1024; no automatic cleanup occurs. During phases, the runner records disk availability every five seconds and aborts before free workspace falls below 512 MiB or /tmp below 256 MiB, then tears down. Initial disk checking happens before Java/Docker startup. Output directories are unique and existing directories are refused.

The sequence is explicit:

1. Confirm fresh source stamp, no Java JVMs, closed service/database ports and no running containers. Refuse rather than reuse a warmed service or interrupt another owner's work.
2. Preserve previous service/GC logs and artifact identity, then run .work/A10/preflight-no-maven.sh. It checks source/fat-JAR hashes, packaged HTML, driver fixture and both JMH method discovery without measurement.
3. Run the frozen up script, require only its own Java PID and exact running source, then scoped reset.
4. Run the frozen benchmark.sh into this run's measurement directory. It executes both benchmark methods at 100/250/500 sizes, three actual forks with three one-second warmups and three one-second measurements plus GC profiler; then all ten corpus inputs three times, each actual solve configured with the 30,000 ms budget, seed 42 and 100,000-step safety cap. The worker may terminate early at a legitimate stop condition; actual durations are retained, never padded.
5. Verify six JMH method/size rows with all forks/iterations, GC metrics and positive throughput; all thirty unique system rows, source/configuration/seed identity, same-input independently checked nondegradation, full feasibility classification, queue/durable times, score traces and actual resource/GC files. Preserve actual improvable-instance outcomes, including a missed 10% tuning goal.
6. Always attempt scoped down after any startup attempt, including failure, timeout, interruption or result-verification failure. Terminate the measured command's entire owned Linux session, including timeout-created process groups. Preserve service/GC logs before and after shutdown. Wait for the owned service, kill only the exact lingering owned JVM if necessary, check the owned Compose label and perform fallback scoped teardown if required. Open owned ports or remaining owned containers produce a failure.

Every phase records the actual argv, exit, UTC start/end and elapsed seconds in operations.json and has a separate raw log. A 2,100-second outer benchmark deadline bounds a hung JMH/driver; the original corpus timeout remains in force. The measurement script's own sampler is terminated with its owned session on interruption. Raw outputs are preserved on failure and never silently accepted as a complete workload. Ctrl-C and TERM enter cleanup; SIGKILL or host loss cannot execute a process's finally block, so the coordinator should run the existing scoped down.sh as the recovery command if it kills the wrapper forcibly.

A successful run leaves operations.json status PASS, validated-summary.json, raw-manifest.json with per-file SHA/size, the exact artifacts-used.json, per-phase logs, preserved pre/post service/GC logs and measurement/{corpus-raw.json,validation-jmh.json,validation-jmh.log,environment.txt,gc.log,server-gc.log,server-resources.jsonl,server-process-status.txt}. The runner's disk samples and process census are observability overhead; other builders/services must remain stopped throughout the reservation. Existing OS/database caches are not flushed; source/import/route JMH boundaries and system run 0 versus 1/2 remain explicit. Three system samples do not justify a p95/p99 estimate.
