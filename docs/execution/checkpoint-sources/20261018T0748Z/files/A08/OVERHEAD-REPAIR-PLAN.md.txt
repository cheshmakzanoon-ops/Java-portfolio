## Ranked implementation candidates and exact locations

These are proposals, not measured speedups. Select runtime changes only after diagnostic evidence.

1. **Primitive consumer drain.** `probe/.../TimingBuffer.java:49` currently allocates Timing from poll; `agent/.../TimingStatistics.java:25` accepts that record; `agent/.../ThreadLensPremain.java:59` consumes it. Add primitive callback/drain and primitive statistics overload, retaining immutable poll compatibility. Copy payload then free the slot/advance head before callback; callback failure must not wedge queue ownership. Test old/new output parity, callback failure, full/empty/reuse, four-producer no-torn/duplicate and accepted+dropped conservation, and shutdown tail.
2. **One thread-local lookup per exit.** `probe/.../TimingProbe.java:10,25–35` gets/sets boxed Boolean state. A per-thread mutable guard retains reentrancy while avoiding repeated ThreadLocal.set operations. Guard exit only, not the application body, so nested application invocations remain timed. One state object per participating thread is an explicit tradeoff. Test recursive/nested/exceptional methods, reentry suppression, fault/reconfigure cleanup, platform/virtual threads and disable races. Keep recoverable-fault isolation and clock boundaries.
3. **Last-subject entry cache.** `agent/.../TimingStatistics.java:25–44` performs TreeMap lookup on each event. Cache last successful ID/Entry without changing first-seen admission, 128-subject ceiling or deterministic output order. Do not cache a rejected subject as admitted. Test repeated/interleaved/overflow IDs, HDR counts/quantiles, exceptional counts, clipping and total duration.
4. **Power-of-two indexing.** `probe/.../TimingBuffer.java:35,51` uses runtime long remainder. Precompute a mask for power-of-two capacities, retain modulo otherwise, never round capacity. Test capacities 2/3/7/64/65536, repeated reuse and concurrent exact publication/drop conservation. Preserve three reservation attempts.
5. **Bounded bookkeeping batches.** `agent/.../ThreadLensPremain.java:49–86` checks clock/disk/shutdown each event and increments AtomicLong for each raw omitted row. Limit batches to 64–256 before checking deadlines/directory; keep bounded deadline response even if queue remains nonempty. Single-writer counters need explicit publication on normal/exceptional consumer exit and truthful status if shutdown cannot join. Test >10,000 events, exact raw-prefix omissions, deadline expiry midbatch, slow consumer, directory fault and discarded tail. Do not merge intentional raw omission with true drop/overflow.
6. **Acquire/release sequence publication.** `probe/.../TimingBuffer.java:36,42,52,54` currently uses full volatile sequence operations. Consider acquire reads/release writes only after higher-confidence changes, with reservation CAS intact and a written memory-order argument: producer observes prior consumer release before overwriting; consumer observes producer release before reading; reclaim release follows payload copy. Repeat no-torn/duplicate/platform/virtual stress. Do not add unbounded spin or weaken publication.

`RecordingController.java` and `EventQueue.java` are separately bounded production paths: preserve 64 MiB retained payload, 65,536 slots, 10,000-entry directory traversal, retained recording/directory limits, callback/consumer failure accounting and drop-to-incomplete windows. Any changes there need their own live/replay regressions and final observer stress, regardless of reference applicability.

## Report-only selection coverage defect

`agent/.../ThreadLensPremain.java:137–153` already exports methodOverflow and policy skips. Its incomplete field describes event collection and does not include registry overflow. `report/.../TimingImporter.java:105–119` ignores methodOverflow/skips; `:134–140` derives incomplete without them; `:180–193` exports no selection-overflow counter. `report/.../ReportDocument.java:82` derives selected-timing missing-data wording from timingIncomplete.

A maxMethods=1 run with two selected methods can therefore omit the ceiling-skipped method without exposing the selection coverage boundary in standalone JSON/HTML. Fix the importer/report only: parse a bounded additive method-selection overflow counter and bounded reason metadata, derive explicit selection coverage, keep queue drops distinct. The existing agent artifact need not change for this adapter correction. Test real two-method/one-ID packaged agent output, retained method timing, skipped method, JSON/schema roundtrip and escaped HTML reason. Negative/oversized/malformed status counters must reject safely. All original reference methodOverflow counters are zero, so this defect does not erase the observed overhead failures or alter their scope.
