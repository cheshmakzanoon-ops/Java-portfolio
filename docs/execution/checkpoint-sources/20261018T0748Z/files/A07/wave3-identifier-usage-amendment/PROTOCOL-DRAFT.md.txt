## Fixed R3 definition

Keep R0/R1/R2 as finite controls from the first draft. Add ONE R3, not an identifier parameter grid. R3 uses the exact R2 DEV-selected prose model, normalization, candidate pool and multiword gates, without an additional fit or independent L2 choice. For actual single unfielded identifiers only, use **query-conditioned distinct resolved incoming caller-members** of exact syntactic name-matched declarations. Qualified/fielded/phrase/Boolean inputs retain existing semantics; no runtime fixture-type tag controls this path.

A member key is opaque `(generation,tenant,repository,source-unit,lexical-owner,signature,source-span)`. It is solely an equality/resolution/deduplication key, never a numeric/categorical learned feature. Source binding uses the actual case-sensitive Java owner/member name and signature; query matching separately retains the existing exact/case-fold identifier policy, without conflating differently spelled source targets. A call edge carries target member, enclosing declared caller-member and source document identity. Lambdas are attributed to their enclosing declared member; repeated calls/method references from that member deduplicate. Self-recursive edges do not create independent callers. Synthetic bridges or implicit compiler-generated calls are not invented.

For each exact query-matched member m, define `usage(m)=min(32, number of distinct resolved enclosing caller-members other than m)`. For a candidate containing multiple genuine exact-name matches, use the maximum over members; never sum file-wide calls or conflate nested owners/overloads. If any matching member is UNKNOWN, the candidate is UNKNOWN too, unless another matching member has already proven the cap32, which cannot be exceeded under this fixed feature definition. The query chooses which name-matched member usage is relevant; querying an unrelated name cannot receive this signal. No source role/path, caller name text, visibility bonus, class count, document length, query ID or grade enters the ranking coordinate.

Every count is **observed resolved caller-member diversity within the authorized indexed snapshot**, a lower bound on possible program usage, never complete-program usage or an intent proof. The eligibility checks below cover only the captured indexed call inventory. Zero observed callers is UNKNOWN for ranking, not proof of no usage. A positive count becomes USABLE_OBSERVED only if the declared indexed-inventory checks pass, or32 distinct proven callers establish SATURATED_OBSERVED. Exact order beyond32 is deliberately ignored. Neither state asserts that external/dynamic/unindexed edges are absent.

Take the exact R0 single-identifier candidate ordering. Collect the positions occupied by genuine exact-name declaration candidates. If ANY candidate in that subset lacks USABLE_OBSERVED or SATURATED_OBSERVED positive usage evidence, preserve the entire R0 query order. Otherwise stable-sort just that subset by descending capped usage, with original R0 order on ties, and put it back into those same positions. Incidental mention candidates stay in their original positions. This avoids a non-transitive pairwise “use count only if both known” comparator and avoids mixing learned prose scores with raw BM25 scores. R3's ordering must be represented consistently in pagination/cursors/explanations; raw BM25 values must not be labeled as the usage ordering score. Identity binds the exact rank tuple rule. No numeric count weight or post-score threshold is tuned.

R3 can change identifier ordering; it does NOT assert caller diversity reconstructs intent. Hard use of a real but noisy heuristic can hurt full graded nDCG. Both full DEV metrics and the frozen two-metric VAL guard determine eligibility/adoption. No later “soft usage” alternative is admitted in this wave.

## Conservative source binding and unknown policy

Use the same isolated quota-bounded parse-only JDK25 worker as the first draft: parse only, `-proc:none`, no analyze/generate/processor/user execution or classpath/network reads. Build source symbols only from indexed source of the SAME tenant/repository and generation. Never resolve a source reference into another repository, including a differently authorized copy of the same package/class. A current authorized repository is a collection boundary, not a promise that it contains every runtime dependency.

Supported rules: lexical owner/scope and private/nest access; explicit fully qualified or unique captured source type declarations/imports; record component return types; explicit parameter/final-field/local types; direct `var x=new KnownType(...)`; and unique declared source method return types. Single-assignment scope/shadowing/reassignment rules apply. Overload selection requires proven receiver/owner and argument/arity/type compatibility; matching terminal names or arity alone never creates an edge. Static imports/nested source owners may be used only when uniquely present in the same source graph. No arbitrary outside class-name lookup table or manually mapped fixture helper.

Generic/lambda inference and polymorphic receivers are not silently guessed. A method reference is counted only when target signature is uniquely established; otherwise it is a potential unresolved call. Unknown receiver, missing/malformed/oversize source, ambiguous owner/import/overload, implicit source generation or uncertain scope is recorded as incomplete evidence. It must not be dropped as if no caller existed. In particular, incomplete generic Key.bytes callers cannot yield a favorable partial bytes ranking. Unknown supertypes/inherited overloads block binding: private/static alone is insufficient (e.g. A.put(Object), inherited B.put(String), put("x")). Null, varargs, unproven `var`/generic/alias receiver and method-reference conversions abstain unless an explicitly frozen supported rule proves the target.

**Indexed-inventory eligibility is not global graph completeness.** It only asks whether the captured authorized source inventory contains unresolved potentially relevant call spellings or unsupported source units. External/dynamic/unindexed callers remain outside the observation; even an eligible positive count is a lower bound. For a private member, inspect its whole source nest; an unresolved possibly matching reference there blocks eligibility. For a non-private member, inspect all source units in its repository scope. Any unresolved call/reference with the same name and potentially compatible signature, or any source unit whose relevant call inventory could not be parsed completely, blocks eligibility for that member unless32distinct proven callers already establish saturation. A receiver proven to be another type is unrelated; an unknown receiver is not. No substring scan is accepted as a substitute for parsing, and unsupported files are not excluded simply to obtain a count.

This strict policy may cause bytes or entire queries to bypass usage. That is the intended abstention behavior. It is preferable to a biased lower-bound popularity score. The implementation may not loosen binding/completeness after seeing DEV/VAL outcomes; a proposed new rule requires a future preregistered version and preserved failures.

## Authorization, generation and quotas

Store source-symbol/call facts in generation-bound repository partitions with exact source/parser/resolver/schema hashes. These are syntactic facts, not precomputed tenant-global popularity. At query time, capture a generation lease and current Access; determine allowed repository scope BEFORE loading any graph/name inventory/count. Resolve/count ONLY inside each permitted target repository partition, then recheck authorization version before ranking/cache/publication. No hidden repository may alter graph-produced owner ambiguity, inventory eligibility, saturation, count, explanation, cached feature payload or ordering decision. Expected graph corruption/missing schema is an explicit integrity/configuration error; deterministic unsupported/quota UNKNOWN invokes the declared whole-query R0 bypass. Neither probes a hidden repository. The existing documented BM25 statistical coupling remains a separate residual limitation; this amendment adds no graph channel. Test graph noninterference against identical captured authorized base candidates, plus end-to-end deny fixtures with unchanged lexical base behavior; do not label the whole old BM25 engine statistically noninterfering. Old cursors still reject any generation change under the existing contract, including a publication that changed only a denied repository; this is distinct from denied data influencing an authorized graph coordinate.

Use a new schema/generation for this graph, not a sidecar stamped over an old index. Atomic publication, recovery, graph checksums, cancellation and retired-reader leases cover all graph files exactly as index files. Permission changes and scope membership are bound to the existing canonical sorted scope/Access version in cache/cursor identity, along with generation, query/mode/profile, full inference+graph schema, catalog and model bytes. Never cache a graph-derived count under only member-name or tenant. Public explanations may show only numeric usage of that authorized candidate/scope, with an explicit indexed-source heuristic label; no hidden names/owner lists/tenant collection counts.

Fixed additional bounds before final protocol freeze:

- Existing source/parse/member quotas from the first draft apply. At most100,000source documents/repository (existing ingestion ceiling),262,144distinct call edges and65,536source member declarations per repository partition, serialized graph≤32MiB. Overflow marks the repository graph incomplete, never a deterministic prefix “complete”; ordinary lexical indexing remains available.
- Per query: existing500candidates, at most128matching members/candidate and64,000distinct matched targets total; at most32distinct callers retained per target. At most65,536graph rows/8MiB scanned/materialized, with no full graph Files.walk/toList. Unsupported/query-budget exhaustion bypasses usage for the entire query with an internal reason, not a partial ordering. No new result/count/facet surface exposes that reason for a denied scope.
- One graph-work admission permit per request; total8 concurrent bounded graph requests, with existing outer admission preserved. Cache max256query-scope entries/16MiB, explicit size eviction. Actual RSS/heap and latency still need a later quiet reference; no current performance pass is extended to this feature.
- Graph resolution/serialization order is canonical; indexes must support name/signature range lookup. Initialization cannot load every tenant's graph into heap. Repeated successful construction from the same complete source snapshot yields identical graph/usage bytes; environment/timeouts abort generation as in the first draft.

Caps are operational bounds, not relevance tuning values. Any implementation-required bound change is reviewed/frozen before scores. Graph UNKNOWN is not a learned feature or an excuse to report a complete-program count.

## Required counterfactuals before scores

1. Same terminal `put` text on a Map receiver cannot count for a custom three-argument helper. Overloaded/nested `bytes` methods do not pool callers. Wrong receiver, shadowed name, ambiguous overload and unresolved method reference cause the declared abstention.
2. Two supported independent callers differ from repeated calls/lambdas inside one caller. Recursive self-calls add none. Repeating a mention/comment/string or adding calls to an unrelated member never changes the query-specific count. Alpha-renaming paths/repositories/member names together with the query preserves diversity/order.
3. Actual private same-owner bounded calls and explicit field/local/declared-return-type put edges from DEV-EVIDENCE are expected binding fixtures, independently asserted from their frozen bodies. The real generic/record bytes references must be recognized or explicitly make that query incomplete, never vanish silently. These are binder correctness tests, not additional relevance labels.
4. Unknown candidate mixed with known candidates triggers WHOLE-query R0 order; pairwise sorting is transitive. Equal eligible positive observed counts preserve exact original order. Saturation32 is stable;32proven callers cannot be misreported as a complete-program total. Full graded list/path ordering is checked, not MRR alone.
5. Adding/removing a denied repository containing same-FQN owners, many callers, malformed source or call-name collisions leaves the authorized graph's feature/order/count/inventory eligibility unchanged, both cold and warmed. Denied callers never cross a source-repository partition. Revoke permission while graph work is in progress and require final Access version refusal.
6. Granting a formerly denied repository yields only that authorized scope's allowed candidates/partition counts. Scope/version/generation/model/schema changes reject old caches/cursors after restart. Actual Boot HTTP and CLI use the same R3 rule and typed OIDC claims.
7. Source update/removal changes the next graph and leaves an active old-generation lease consistent; corruption, crash between graph commit/pointer publication, quota overflow, disk-full and cancellation do not publish a half graph. Old gen recovery stays usable; no stale identity stamping.
8. Generated distinct fake callers can inflate this heuristic despite deduplication: document this search-spam limitation and cap it; do not claim adversarial semantic truth. No role-based exclusion of tests or “less useful” callers is allowed to repair a metric.

## Finite training/selection amendment

R1/R2 still have ONLY `{.1,1}` L2, same17groups/fiveDEVfolds/seed7007 and strict original optimizer budgets. R3 reuses the fixed R2 selected model; it introduces NO new optimization or weight. Maximum remains20fold fits+2refits. If R2 has no eligible complete DEV trial, R3 is ineligible too; no substitute R1/C1 prose model is selected after results. Compute R3 DEV OOF metrics from the already fixed corresponding R2 OOF predictions plus its deterministic identifier usage rule, with the full40DEV ideal denominators and no oracle document insertion. It must pass the same joint nonregression guards against R0/originalBASELINE. Do not claim in-sample identifier/source inspection proves generalization.

Freeze all eligible R0/R1/R2/R3 models/rules before the single20VAL family-selection phase. Same objective: maximize min(nDCG/.75,identifierMRR/.90), with both metrics nonregressing against R0 and originalBASELINE. Equal objective selects originalBASELINE, then R0, R1, R2, R3 in that order. No full goal can be declared merely from DEV/VAL. All graded nDCG, MRR, paths, failures, bypass counts and graph-inventory eligibility reason audits are preserved; the latter are offline diagnostics, never inferred from heldout outcomes.

Add ONE diagnostic mask NO_MEMBER_USAGE, which gives the corresponding R2 identifier ordering exactly. The complete finite mode list is the first draft's12modes plus NO_MEMBER_USAGE (13total). NO_IDENTIFIERS, NO_CODE_FEATURES and BASELINE also disable usage. All other masks keep the same usage graph rule while masking their declared prose/source channels. Diagnostics do not select a winner. Repeated VAL and prior heldout exposures remain disclosed; no new heldout opening or test-winning ablation adoption follows automatically.

The final eventual service/CLI model identity must include R3's resolver, graph schema, count cap, subset stable-sort, indexed-inventory eligibility policy and authorized-scope digest. A newly adopted R3 deployment may improve either required metric or fail both; actual guarded evaluation decides. The amendment removes the architectural guarantee that identifier MRR stays unchanged without manufacturing a guarantee that it improves.
