# Pre-measurement scope and completeness corrections

This implementation clarification preserves the two frozen scratch drafts and addenda1/2. No wave3 feature export, fitting, new metrics or validation has run. It introduces no family, dimension, grid value, vocabulary or relevance-label change.

The conservative binder does not flatten a field and a same-name local from later or disjoint lexical scopes into one symbol. A member containing such field/local shadowing is unsupported for binding; affected caller evidence is UNKNOWN rather than assigned to an arbitrary local. This may abstain on resolvable Java, and does not claim javac attribution. Duplicate local names and parameter reassignment retain their existing conservative handling.

Implicit unqualified invocation syntax has a distinct typed receiver marker. Static-import lookup is unsupported; its potentially relevant calls make a count incomplete. An enclosing-owner lookup without an explicit supported inner-owner method group is likewise UNKNOWN. Explicit `this.method` and an explicit supported source receiver remain distinct. Private/static declarations alone do not prove lookup/overload resolution. A skipped lambda body records incomplete call inventory; it cannot silently contribute a complete zero. Saturation32 can settle usage-count uncertainty only after declaration-subset membership is complete, as in addendum1.

A terminal if-guard is emitted only when the if itself is an immediate statement in its actual lexical block's statement list. An unbraced nested conditional/loop does not inherit outer-block dominance. Braced children have a different block identity. A guard must precede a supported effect in the same modeled statement list and concern the same supported provenance. Conditional, arithmetic, field/array-state, escaped and unresolved transformations do not acquire a primitive parameter-type producer anchor; only the direct parameter or a proven single-assignment local alias does. Unsupported loop accumulators remain UNKNOWN rather than claiming a bound/safety proof. Feature14/15 describe observed guarded/alternate syntax, never whether a comparison enforces the user's intended policy.

The query view loads only authorized repositories, separately partitions their resolution environments, and checks authorization before summary/graph bytes and again before release. All selected partitions together have at most8MiB decoded summaries and65,536 materialized document/type/member/call rows, with a separate65,536-step inference budget and8 admission permits. Exceeding a deterministic query quota discards the entire view's added evidence/usage order. Corruption, schema/configuration mismatch or admission failure is an explicit error, not a prefix treated as complete. No tenant-wide graph cache is introduced; zero cached graph entries is within the declared maximum. Random generation IDs remain outside canonical graph bytes.

The source summary wire validates each expression kind's child shape before any binder assumes a receiver/argument exists. Compressed frames reject truncation, dictionaries, malformed data and trailing compressed bytes. Unsupported JDK formal types remain distinct unsupported signatures rather than collapsing generic overloads into the same empty-string signature. The immutable API catalog, worker bytes and exact parser JDK build must agree at configuration and generation use. Existing tenant-reader BM25 score/order statistical coupling remains the separately documented limitation; no ACL statistical noninterference is claimed.

Direct counterfactual source tests cover the independently reviewed field-shadow, nested-unbraced-if/loop and static-import/enclosing-call defects. They remain unverified until the next explicitly granted development run, followed by full integration/coverage/mutation certification before any study execution.
