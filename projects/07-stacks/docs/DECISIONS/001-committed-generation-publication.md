# ADR001: publish complete committed tenant generations

Status: implemented; current verification is recorded in [status](../STATUS.md). Performance and relevance measurements remain separate.

A reader must never combine old and new document revisions, and a process can fail after an atomic pointer replacement but before the ingestion caller observes success. Updating an index in place and treating a missing completion marker as permission to replay would violate these requirements.

Each tenant publication builds a complete generation in staging, commits Lucene with manifest/job metadata, computes checksums, and warms a committed reader before publishing a checksummed CURRENT pointer through atomic replacement and durable file/directory writes. PREVIOUS supports verified fallback. Leases keep already acquired readers alive while a newer generation becomes current; retirement waits for the last lease before closing and pruning. Startup validates pointers, checksums and commit metadata, quarantines incomplete/corrupt artifacts, and fails explicitly when no trustworthy generation can be selected. A data-directory lock enforces one application owner, and a per-tenant lock serializes its writers. This is a local filesystem design, not a distributed writer protocol.

The committed job identity is authoritative at an ambiguous publication boundary. Before another tenant publication and during startup, the engine reconciles that committed identity with parsed checksummed completion receipts. Receipt existence alone is insufficient: malformed records fail status, resume and startup instead of silently declaring completion. This prevents jobA, committed before an AFTER_POINTER/RETIRE failure, from later replaying over a successful newer jobB. Live/restart A→B→resumeA regressions assert that B survives. Stable document paths are configured-repository-root-relative, so a full directory followed by a selected nested file updates the same key.

We rejected in-place mutation because it complicates snapshot visibility and rollback. We rejected success based only on CURRENT replacement or receipt existence because either can hide an unknown outcome or corrupt metadata. We reuse Lucene's index and commit implementation; generation coordination, manifests, receipts, fault schedules and lease protocol are original project code.

The cost is rebuilding a complete tenant generation and temporarily retaining more disk data. Source-byte, document and ingestion quotas bound accepted work; the design does not promise unlimited repository size. Atomic rename and directory fsync depend on the supported local filesystem. Kernel /dev/full tests prove a real write failure before publication, not a filled production index volume. One hundred seeded fault schedules and the independent stale-replay regression provide bounded evidence, not a proof against every storage/controller failure.
