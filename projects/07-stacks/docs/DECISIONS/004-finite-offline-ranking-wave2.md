# ADR004: finite syntax and declaration challengers with development-only learning

Status: implemented and historically evaluated as build25; relevance targets remain unmet.

The development/validation review justified testing whether the handcrafted identifier channel should apply to plain multiword queries. Bare-identifier collisions often contained several real declarations, which did not justify a project, visibility or body preference. The registered families were C0 CLASSIC, C1 syntax gating, D1 an exact syntactic declaration tier, and conditional C2 shared-feature linear pairwise learning, alongside the original content baseline. Equally real declarations retain deterministic base order; explicit query syntax, single-identifier bypass and feature ablations remain defined.

C2 receives ten bounded query/candidate interaction features over at most 500 authorized candidates. It cannot insert judged positives, learn document/term/project identifiers or use grade-derived query types. Deterministic grouped development folds keep identical complete judgment vectors together. Equal-query scaling is fitted within each training fold. Three fixed L2 candidates use bounded pairwise logistic optimization and full-list nDCG/identifier-MRR guards. Missing retrieved positives remain in ideal-gain denominators. Validation supplies no gradients or parameter adjustments; it selects among the frozen families using the two-metric objective and no-regression guards.

Model bytes contain finite coefficients, scaler values, schema and provenance under checksum and byte quotas. CLI and Boot load an immutable configuration snapshot. The complete supported inference artifact, Lucene dependencies, actual numeric profile and model/scaler digest bind scoring, cache and cursors. Exploded development origins include all original classes instead of relying on a transitive handwritten class list. CLI and Boot package identities differ; configuration and model semantics remain shared. Runtime bytecode redefinition is outside this identity boundary.

Separate label-blind audit, development-only fit and frozen validation phases use non-overwriting outputs and reject changed identities. C0 must exactly reproduce the 540 historical development/validation metric/path rows before selection completes. The runtime has no wave2 held-out command. Historical final execution used a separate versioned operator and durable seals, preserving the earlier final results. Repeated exposure of the authored held-out corpus is a limitation; it cannot be described as a fresh blind test.

Build25 passed 88 tests and recorded 524/628 strict mutation kills. Its finite development/validation procedure selected C1. The final 20-query comparison produced nDCG@10 of 0.6594266978 and identifier MRR@10 of 0.8000000000, versus baseline 0.6012721858 / 0.8833333333. The no-regression guard retained baseline; neither configuration met both 0.75 / 0.90 targets. Fit failures, comparisons, result envelopes and seals remain preserved. Current source verification is recorded separately in [status](../STATUS.md).

The feature family does not remove tenant-wide BM25 statistical coupling. Lexical features do not prove symbol attribution, executable behavior or same-method relations. Later serving and source-export refactoring shares one ranking/ablation policy without changing these historical results or making an adoption claim.
