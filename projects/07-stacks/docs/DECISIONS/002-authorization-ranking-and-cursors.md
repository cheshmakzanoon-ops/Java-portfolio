# ADR002: filter every search surface and bind pagination context

Status: implemented; certification23 passes. Tenant-reader BM25 statistical coupling is an explicit remaining limitation approved within the Lucene/filter scope.

Authenticated HTTP verifies real signed OIDC tokens, including original signed JSON claim types, rather than trusting Nimbus's converted subject value. Raw-byte admission bounds work before request parsing. The CLI is a local administrative interface to the same application services. Domain, ingestion, index and query code remain independent of Spring; Boot supplies the repository-convention HTTP/security adapter.

Every candidate query includes tenant and current repository permissions. Counts, facets, suggestions, snippets, explanations and bounded response-cache paths apply the same authorization boundary, and permission versions are rechecked before returning. Cached entries cannot bypass revocation. User explanations expose authorized matching feature names and numeric scores, not raw Lucene n/N/avgdl statistics or denied repository counts. Actual denied-repository, warm-cache and revocation controls exercise these surfaces.

We keep tenant-wide Lucene readers for practical generation reuse. Their BM25 statistics can still change numeric scores and ordering when inaccessible repository documents change. Removing raw statistics closes a concrete disclosure but does not establish statistical noninterference. Per-permission-subset indexes or custom authorized collection statistics would add a different indexing/ranking design and are not claimed implemented. Timing is another separate observable.

A signed cursor binds tenant, authorization version, canonical principal/actual sorted repository scope/admin role, query/filter/scoringVersion/profile digest, generation, offset and a300-second expiry. The principal uses unambiguous UTF16-code-unit canonicalization before hashing, preserving opaque newline subjects without delimiter or replacement aliases. Same-profile restart can continue; changed-profile or same-version changed-scope restart rejects. The HMAC key is persisted privately. Signing prevents tampering; the payload is not encrypted. The cursor cap is2048 bytes, with explicit signed2047/2048 acceptance and2049 rejection tests.

We rejected relying on a restart-local permission counter alone because equal versions can describe different scopes after restart. We rejected cursor reuse across ranking profiles because its offset would refer to another order. The earlier implementation still filtered unauthorized result content, but did not reject those pagination-context mismatches. The runtime exposes ranking mode/profile through actual CLI JVM properties and Boot Environment configuration, verified through HTTP. BASELINE/CURRENT remains the default pending final quality acceptance; prepared reference data explicitly uses CODE_HIGH/SOURCE_AWARE rather than assuming an evaluation-only setting.


Independent review subsequently found a request-context collision: Java Map display strings render a literal kind value `source, language=java` identically to separate kind/source and language/java filters. That representation was unsuitable for either response-cache keys or cursor digests: a warm response could violate exact filter semantics even though tenant/repository authorization still applied. The implemented correction uses a versioned binary tuple with filter count, sorted length-prefixed UTF16 key/value strings, query text, page size, mode and scoringVersion. UTF16 code units avoid replacement aliases, and explicit lengths avoid delimiter aliases. Build24 strict certification65tests/98mutants and independent review close the direct cache/cursor/reordered-map/restart/revocation regression. The subsequent first frozen held-out study failed quality and retained baseline, independently of this correctness repair.
