# Engineering review

The current design review follows posting, reversal, period closure, idempotency, source statements, reporting, and reconciliation from HTTP identity through PostgreSQL commit and recovery. It covers all 18 production classes, all three migrations, and the shared source-audit SQL. [Architecture](ARCHITECTURE.md) maps the source and transaction boundaries; [invariants](INVARIANTS.md) ties each guarantee to enforcement and a falsifying regression.

## Findings and resolutions, 2026-10-20

| Severity | Confirmed failure | Resolution and evidence |
| --- | --- | --- |
| High | A retryable connection-close exception after an acknowledged commit could replay a completed callback or report rejection after success. | `SerializableTransactions` records commit acknowledgement separately from cleanup. A close failure returns the committed result and records a warning. A regression injects SQL state `40001` on close and proves one callback execution. Unknown commit acknowledgement remains a caller recovery case. |
| Medium | SQL's `digest <> NULL` did not reject an existing receipt; nullable operation identity reached receipt lookup. | V3 validates required identity and `POST`/`REVERSE` consistency before lookup and uses `IS DISTINCT FROM`. Raw runtime-role calls verify rejection without extra source/receipt/outbox rows. A V2 database upgrades without rewriting valid receipts, balances, or grants. |
| Medium | Malformed UTF-16 references could collapse to replacement bytes during canonical digest encoding. Invalid signed subjects and audit fields could also fail only at storage. | `LedgerText` enforces lossless NUL-free PostgreSQL UTF-8 at the relevant domain/identity/audit boundaries. Distinct malformed references cannot acquire the same accepted digest; actual RSA-signed malformed subjects are rejected. Valid accented, CJK, and supplementary text remains intact. |
| Medium | CSV decoding silently replaced malformed UTF-8. Parsing and hashing inside retried transactions also repeated non-database work and depended on mutable input bytes. | Strict decoding rejects malformed bytes and NUL before connection acquisition. `StatementCsv.Prepared` owns immutable rows and a raw-byte content hash reused across retries; matching remains transactional. Boundary and PostgreSQL regressions verify no partial import. |
| Medium | Two manual decisions could repeatedly collide on one candidate and surface a generic database rejection after exhausting uniqueness retries. | Each decision rechecks candidate availability inside its retried transaction. A forced two-transaction race yields exactly one match/audit and one explicit `INVALID_MANUAL_CANDIDATE`. |
| Medium | A rollback exception replaced the primary transaction failure and could change a permanent rejection into a temporary connection failure. | Secondary rollback failures remain suppressed on the primary SQL, application, or fatal failure. Regressions preserve classification, original cause, cleanup, and interrupt state. |
| Medium | Catching arbitrary null dereferences as client validation concealed application defects. | Required domain/DTO fields fail explicitly with `MISSING_FIELD`; only known validation exceptions map to client errors. Unexpected null dereferences remain server failures. |
| Medium | Workload shutdown joined writers but did not join the database sampler before final observations and pool teardown. | Both executors now terminate within one shared deadline. A real-thread fixture delays sampler exit, proves cleanup waits, and preserves an already-interrupted caller. No workload measurement was rerun. |
| Low | CSV export depended on JDBC result-map iteration and could expose accidental extra selected columns. | Export uses the fixed contract column list, with quoting and formula neutralization; a reverse-ordered map with an internal extra key produces the expected public CSV. |

No confirmed high- or medium-severity finding from this scope remains open. This conclusion is bounded by the documented threat model and executed fixtures, not a claim of production readiness or exhaustive defect absence.

## Local lifecycle findings

The earlier launcher trusted PID/command text, left acquired resources on readiness/seed failure, and did not wait for API exit during shutdown. Kernel start/boot identity and exact artifact provenance now control process authority. Startup records preexisting all/running containers, avoids implicit recreation, and rolls back only acquired resource transitions while preserving its primary failure. Shutdown is bounded and retains ownership records on an identity mismatch. Separate process/control regressions cover readiness and seed failures, preexisting API/container preservation, stale artifacts, reused identity refusal, cleanup errors, terminal cancellation, and TERM-resistant processes. These are control-adapter tests; the current live image/lifecycle run is recorded separately.

## Executed evidence and limits

The current full build passed 67 methods and both unchanged mutation gates; exact outcomes, surviving mutations, and source hashes are recorded in [verification status](STATUS.md) and [current evidence](../evidence/engineering-verification-2026-10-20.json). The projection race expects cash debits/credits 350/100 and revenue 100/350 after two postings and one reversal. The failure fixture raises a database error after checkpoint insertion and proves membership/deltas both roll back before retry. These expected states are computed independently of production projection code.

The period lock deliberately serializes writes within one tenant/period, and the reversal adapter uses the original period. Unknown commit outcomes require the retained key; individual database/pool timeouts are not an end-to-end deadline. Trusted runtime credentials and DBA actions remain outside tenant-user isolation. Production capacity, regulatory suitability, a full quiet-host reference study, and clean-checkout release reproduction remain unestablished.
