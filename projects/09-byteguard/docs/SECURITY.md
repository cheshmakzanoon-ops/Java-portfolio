# Security and trust model

This is an offline CLI analyzing untrusted classfile bytes under explicit bounds. It has no listening service, authentication layer, tenant state or credential store. The trusted boundary includes the analyzer distribution, JDK, pinned dependencies, rule configuration and owned fixture compiler; target archives remain untrusted. Rule sanitizer entries are assertions about exact descriptors and contexts, not inferred proof of arbitrary sanitizer implementations.

Inputs and dependencies are explicit local paths. No network resolution, target classloader, reflection, Java object deserialization, annotation processing or execution of analyzed bytecode is used. Owned fixture compilation always supplies `-proc:none`. Archive entries are streamed into bounded byte buffers and never extracted; traversal names, duplicate entries/classes, symlinks, nesting, corrupt CRCs and unsupported versions fail with diagnostics. Expanded bytes and deadlines are enforced from actual reads. Multi-release selection follows manifest semantics rather than counting all variants as application classes.

Parsing and analysis have independent structural/state limits as well as a shared work/deadline budget. Iterative hierarchy, SCC and heap-alias traversals avoid recursion proportional to an adversarial inheritance/call/reference chain. Unknown/native calls conservatively propagate uncertainty to returns and mutable receiver/argument contents, including void calls. Unsupported bootstrap/lambda effects retain explicit partial coverage. Unknown is distinct from clean bottom.

The CLI intentionally writes the caller-selected report/explanation paths and project-local demo/benchmark state. Supply output paths the caller owns. Source metadata is sanitized for SARIF; absolute workstation paths and source contents are not embedded as routine finding evidence. Do not put secrets into rule files or archive names. Reports may expose method names, source basenames, modeled source/sink descriptors and instruction identities; treat reports according to the sensitivity of the analyzed program.

The pinned SARIF2.1 schema and upstream license are preserved under `contracts/`; tests validate actual complete, error and partial reports. Baselines use exact finding fingerprints, with no broad filename suppression. Every resource-limited scan exposes terminal status and machine-readable unfinished coverage.

This project does not claim a complete verifier, universal soundness, exploitation proof, filesystem race protection or safe execution of target code. Path fixture validation is lexical and assumes an owned symlink-free root. Weak object-insensitive heap aliases and coarse shell-array modeling have reproduced false positives outside the preregistered corpus. Details, concrete controls and unsupported behaviors are in [THREAT-MODEL.md](THREAT-MODEL.md), [INVARIANTS.md](INVARIANTS.md) and [REVIEW.md](REVIEW.md). An empty result must never be advertised as security certification.
