## Encoding and transaction diagnostics, 2026-10-20

Two maintenance findings concern data fidelity and failure handling:

- CSV ingestion previously used UTF-8 decoding that replaced malformed bytes. Distinct invalid byte sequences could therefore become the same decoded reference or source identity. Ingestion now rejects malformed encoding and NUL before database access. Regression fixtures cover truncated, invalid continuation, overlong, and surrogate encodings; PostgreSQL coverage verifies intact accented, CJK, and supplementary characters and no partial import after rejection.
- A rollback `SQLException` previously replaced the failure that caused rollback. A permanent business/database rejection could consequently acquire an unrelated connection-error classification and lose its original cause. Rollback failures are now suppressed on the primary exception. Regressions preserve SQL and application failures, retry classification, connection cleanup, and the diagnostic chain.

These changes leave posting SQL, lock order, money semantics, and retry budgets unchanged. Current execution outcomes are recorded in [verification status](STATUS.md); historical performance results apply to their original source identities.
