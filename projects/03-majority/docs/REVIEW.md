# Correctness and ownership review

The review covers every production class in all six modules. The [architecture map](ARCHITECTURE.md#source-boundaries) links their responsibilities; [invariants](INVARIANTS.md) connect guarantees to executable counterexamples. Historical evidence certifies its recorded source, not subsequent changes.

## Protocol and storage findings

| Priority | Trigger and failure | Correction and regression |
| --- | --- | --- |
| High | A snapshot acknowledgment arrives after several 50-ms heartbeats. Each retry previously replaced the sole accepted correlation, so every delayed response became stale and a healthy follower could never catch up. | Retain the outstanding chunk request until progress or restart. `SnapshotTransferTest` delays every reply for three heartbeats and drops acknowledgments, then verifies current-term commitment resumes. |
| High | An owner action fails after partially changing protocol state, while later actions are already queued. Admission-only failure checks let those actions execute on the failed state. | `NodeExecutor` checks terminal state immediately before execution, including disk failures. Latch-controlled tests queue work before both failure kinds and prove it cannot execute or acknowledge persistence. |
| Medium | Two valid `Durable` values contain different uncommitted payloads at the same index/term. WAL delta sharing compared only coordinates, so memory changed while restart retained the old command. | Immutable commands have semantic byte-array equality; shared-prefix detection compares full entries. A real journal reopen verifies the replacement bytes. |
| Medium | Persistence fails after writing bytes or publishing part of a generation, then a caller retries on the same object. Appending behind an uncertain tail or old generation can corrupt the recovery path. | The journal becomes permanently failed until close/recovery. Fault injection verifies no second append occurs and the prior acknowledged prefix remains recoverable. |
| Medium | A future caller attempts to change a granted vote within its term, replace committed entries, alter a published snapshot at the same coordinate or move snapshot state backward. | Journal transition checks reject those changes before writing. Real-file tests verify unchanged WAL size and recovered state. |
| Medium | A repeated snapshot chunk arrives after its reply was lost. The old assembler restarted or rejected already received bytes. | `SnapshotAssembler` owns transfer identity, declared length, exact last-chunk comparison and bounded assembly. Duplicate, overlapping, missing-prefix, conflicting and corrupted schedules preserve activation boundaries. |
| Medium | Checksum-valid snapshot metadata duplicates a client ID or contains malformed retry receipts/coordinates. | Reject ambiguous identities and invalid sequences/digests/results before activation; retain the earlier adversarial recovery fixtures. |

No election algorithm or acknowledgment rule was replaced. Persistent single votes, current-term majority commitment and fresh quorum reads remain explicit. There was no pre-vote, check-quorum lease or dynamic membership when this review was written; pre-vote, check-quorum and leadership transfer were added afterwards (see [architecture](ARCHITECTURE.md#liveness-hardening-pre-vote-check-quorum-and-leadership-transfer)). Dynamic membership is still absent. New validation and refactoring retain wire/WAL version 1; no data migration is required for valid existing state.

## Transport, lifecycle and verification findings

| Priority | Trigger and failure | Correction and regression |
| --- | --- | --- |
| Medium | Concurrent client requests race the `pending.size()` check and insertion. Close also races channel publication and leaves outstanding waits blocked. | Atomic admission permits, separate mutation/lifecycle ownership and terminal future completion. A real TLS test holds 256 requests, rejects 44 concurrent excess calls and resolves all accepted calls on close. |
| Medium | A local unauthenticated process retains all inbound slots with silent connections. | Three-second handshake/first-authenticated-frame deadlines; 64 real stalled sockets expire before an authenticated request succeeds. |
| Medium | Node construction acquires its journal lock and subsequently fails while loading TLS, or startup cannot bind its configured port. | Staged construction and failed-start cleanup release owned resources while preserving the original error. TLS event loops are allocated only after certificate setup. Missing-certificate and occupied-port regressions immediately reopen the journal. |
| Medium | Shutdown stops disk admission before queued protocol work can no longer emit persistence, ignores executor termination failure, or skips writer cleanup after transport teardown throws. | Close admission first, abandon queued protocol work, finish admitted writes and release storage last. Preserve primary/suppressed errors and retain the journal after writer timeout. Tests cover active writes, protocol/disk deadlines, interruption and unchecked transport-close failure. |
| Medium | Certificate generation fails after credentials were published; a later constructor mistakes their presence for completed TLS setup. Timed-out helpers can also remain alive. | `LocalTlsIdentity` stages/validates the identity and publishes credentials last, preserving older credentials during partial recovery. Failure/retry and real timed-out child tests verify cleanup. |
| Medium | The fault demo records a GET interval after the request completed and starts an uncertain mutation's interval before an unrelated read. These intervals weaken the independent check. | Capture each actual invocation and response around its own call. The checker retains its separate sequential model and bounded inconclusive outcome. |
| Medium | Random simulation repeatedly reuses sequence one with changed payloads, so later mutations mostly exercise identity conflicts. Healing checks only observe a leader. | Distinct bounded identities continue changing state. Every extended seed must commit a fresh post-heal command and converge its value on all three members. |
| Medium | A stop-only controller generates TLS files, or a repeated workload invocation replaces existing measurement metadata. | Stop controllers require no provisioning; workload outputs must be fresh. Tests preserve absent TLS state and existing result bytes. Measurement metadata excludes arbitrary application properties. |

Role configuration is defensively copied, replies bind the expected member and destination role, and helper deadlines terminate their owned subprocesses. Fixed-membership administration and recovery validation are specified in [operations](OPERATIONS.md) and [security](SECURITY.md).

## Certification and limits

Current results belong in [STATUS.md](STATUS.md). Mutation scope includes the original `Raft` and `Registers`, the extracted `SnapshotAssembler`, and the `NodeExecutor` lifecycle state machine. Both the core and lifecycle module gates require 70% strict kills. Survivors, uncovered mutations and timeouts remain visible and penalized in the denominator. Adapter behavior is also exercised through actual TLS sockets and independent JVMs.

The full 100,000-operation/profile/concurrency performance study remains open. Simulator seeds and bounded histories are not a universal consensus proof; process tests share one host and do not establish power-loss or whole-machine tolerance. Clean-checkout/full-reactor/hosted release checks remain separate from project correctness certification.
