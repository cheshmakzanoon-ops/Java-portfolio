# Engineering case study

A leader flag is not evidence that a read is safe: an isolated old leader can retain that flag after another majority has elected a replacement. Majority therefore treats each read as a fresh correlated quorum exchange, after a current-term marker has committed, and waits for the captured safe index to apply. The actual-process demo deliberately keeps the former leader alive while excluding both peers and asserts that its local map cannot produce a successful read.

The first seeded simulator run found a real ordering defect at seed 27: application advanced before its commit persistence acknowledgment, even though client replies were withheld. A crash could then make the observed application index decrease on restart. The correction moved application and received-snapshot activation into the matching persistence-acknowledgment handler. A named crash-before-ack test and the seed27 schedule preserve that counterexample. Review also identified a FIFO-drain defect and unexpired pending reads; both now have named regressions.

Append-only replacement transactions avoid a second class of failure: overwriting a divergent suffix in place can destroy an old complete recovery path before its replacement is durable. Snapshot publication similarly preserves the previous generation until a verified snapshot and fresh WAL are selected by a durable atomic manifest. Complete corrupt records cause startup refusal; only structurally incomplete final records are eligible for tail recovery.

Recovery validation must protect semantics as well as bytes. A checksum-valid snapshot could previously list one client twice and silently replace its retry receipt in the session map. Recovery now rejects duplicate identities and validates each sequence, digest, committed outcome and snapshot coordinate. Regression fixtures deliberately recompute valid checksums over malformed content, so passing integrity checks cannot conceal an invalid client history.

Snapshot recovery exposed a different problem: valid acknowledgments that arrive later than a heartbeat must still count. The sender previously allocated a new request correlation on every retry and rejected the delayed reply for its predecessor. Keeping one outstanding identity until the chunk advances restores progress. A deterministic transfer schedule now delays each reply across three heartbeats, loses acknowledgments and repeats chunks before checking that the follower catches up and a new current-term command commits.

Resource ownership is part of the correctness boundary. Admission checks cannot protect a failed state machine from work that was already queued. The extracted `NodeExecutor` checks state at execution, stops protocol admission before closing disk admission, and waits for admitted writes before the journal lock can be released. Latch-controlled schedules exercise failure, full queues, shutdown deadlines and interruption without relying on chance. Persistence failures poison the journal until reopen, because the last attempted transaction may already have written or published bytes even when its caller did not receive success.

This is educational evidence under explicit stable-storage and non-Byzantine assumptions. [Verification status](STATUS.md) records executed gates, bounded-search outcomes and unfinished acceptance work; it does not claim production field experience or a universal consensus proof.
