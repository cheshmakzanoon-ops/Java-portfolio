## Structural changes

`Store` remains the compatible application facade and owns no SQL. `ProblemRepository` owns immutable inputs; `SolveJobRepository` owns admission, leases, progress and terminal transitions; `PlanRepository` owns publication and residual revisions. `JdbcTransactions` owns connection lifetime, binding and rollback. Their transaction and lock contracts are explicit in [ARCHITECTURE.md](ARCHITECTURE.md). `PlanningTask` contains candidate construction; `Dispatcher` contains execution ownership. `ApiErrors` contains HTTP failure policy.

The decomposition leaves DTO names, HTTP routes and stored JSON shapes intact. Schema changes are additive and validate existing rows. Project POMs were formatted without changing project dependency versions or plugin semantics; shared dependency patches are inherited from the parent baseline.

## Retained constraints and evidence

The earlier cross-origin development-mode, strict-CSP, JSON-coercion, source-compatibility, cancellation-start and URL-identifier fixes remain in place. The failed eval-based browser harness and failed historical performance studies remain recorded. Browser assertions use locator APIs under the real CSP; no `unsafe-eval`, policy bypass or weakened coverage/mutation threshold is introduced.

One declared depot, stop-boundary observations, no cargo transfers, no explicit returned-to-depot observation event, cooperative cancellation and retained-storage process recovery remain model limits. A schema-owning startup role, retention policy, production TLS/credential operations and deployment availability need an actual operational deployment; local tests do not supply them. Historical performance must be rerun before being attributed to the changed runtime. No new benchmark is part of this change.
