# Measurement protocol

No target is a result until a raw artifact and matching source fingerprint exist. See STATUS for actual completed runs.

`projects/08-backtrace/scripts/benchmark.sh` runs four declared workloads (`cpu`, `allocation`, `contention`, `virtual`). Each has seven paired blocks, randomized baseline/JFR/JFR-plus-selected-instrumentation order using seed 42908. Every JVM has a 30-second warmup then a 60-second measurement; total fixed observation time is 126 minutes (84 JVMs), plus startup/recording output. Baseline observations are shared within each three-mode paired block. A separate `--smoke` path uses one block / 0+2 seconds and is labelled ineligible for acceptance.

Current benchmark reproduction uses **v3-allocation50-park-class-only**: all six event categories, execution 20 ms, weighted allocation **50/s**, monitor/park 2 ms, allocation/monitor stacks enabled and park stacks disabled. Fresh v3 cause validation passed CPU 7/7, allocation 7/7 and contention 7/7 at 2026-10-18T07:05:14Z (`../evidence/planted-cause-v3.json`). The current observer passed 1,202.669 seconds of functional stress at 08:31:25Z (`../evidence/observer-stress-v3.json`). The full 84-JVM overhead rerun remains pending. The completed first 84-JVM study failed; its archived settings and results remain separately identified below.

Raw per-process outputs include exact command, order/time, mode, workload rate, operation count, throughput, p50/p95/p99 latency, GC collection/time deltas, process peak RSS (Linux /proc), JDK flags and runtime/hardware/cgroup metadata. **Archived first-study settings (study8)** were execution 20 ms, weighted allocation **150/s**, monitor/park 2 ms with stacks enabled, plus GC and JFR loss events. For both configurations, heap is fixed 256 MiB, ActiveProcessorCount=4, and event settings stay constant across compared trials within that study. RSS is the process-lifetime Linux high-water mark (including warmup/startup). GC deltas begin at measurement start and are read after recording stop/dump, so that small finalization interval is included. Selected instrumentation is exactly plantedCpuHotspot/plantedAllocationPressure/plantedMonitorContention, at most three IDs.

The measured boundary is host-workload operation throughput/latency while minimal JFR records to disk and, in instrumented mode, the startup probe consumer aggregates selected-method timings. Offline report generation runs after recording and is outside this overhead boundary. Live callback/slow-consumer boundedness is exercised separately by the1200-second observer stress.

The workload driver is closed-loop. It measures operation duration after a worker starts work and does not account for arrival-queue delay; coordinated omission is explicitly declared. Contention has four platform workers; virtual uses four virtual workers; CPU/allocation use one worker. This is an experimental reference workload, not an end-user service latency claim.

Paired effect estimates operate on within-pair log ratios and exponentiate geometric-mean/median effects. Approximate 95% Student-t intervals assume independent paired log effects; seven pairs use df=6 and t=2.447. These intervals describe run variability on the declared host, not universal overhead. The gate is median throughput regression <=5% JFR / <=10% selected instrumentation and median p99 regression <=10% / <=15%. Every trial is retained, including failures. Directory or probe disablement invalidates an instrumentation trial.

Full trials require an exclusive reference-host window. Shared-host functional stress is intentionally labelled and cannot establish an overhead gate. The 20-minute stress exercises cardinality/slow consumption, live JFR, platform/virtual host progress, overflow/drop counters, incomplete windows, observer-directory and heap bounds, and secret-exclusion assertions. Synthetic cardinality ingress is marked separately from JFR events; its sample counts are not claimed as native CPU observations.

### Acceptance fail-closed changes

The full BenchmarkRunner now raises a failure after retaining all raw trials when any
throughput or p99 regression exceeds its published limit. Every instrumented
trial requires an exact, complete terminal observer status: no drops, overflow,
probe failures, shutdown loss, premature termination, missing quiescence or
mismatched accepted/observed timings. A smoke study is always explicitly
non-certifying and does not claim the P08-A5 threshold. This change itself
requires current-source Java 25 tests and a fresh 84-JVM quiet-host run;
it does not turn the historical failed study into a pass.
