# IndexForge invariants

| Boundary | Invariant | Implementation and evidence |
| --- | --- | --- |
| Input identity | Stable key is tenant/repository/configured-source-root-relative path, preserved for nested file/directory selections; immutable manifest hash and repository-scoped retry key identify the same job. Changed content under the same key conflicts. | SnapshotManifest canonical constructor/serialization; IngestionJob durable registration;10k-record retry and manifest round-trip tests. |
| Durable job outcome | A committed job cannot replay over a later revision, even when publication returned an unknown outcome. Completion receipts bind schema/job/manifest/generation and verify checksums before status or retry. | Build17 commit-metadata reconciliation before startup/later tenant publication; AFTER_POINTER/RETIRE × live/restart A→B→resumeA and corrupt receipt status/resume/startup regressions. |
| Input acquisition | Explicit source selection never executes source/builds/classes. UTF8 decoding is strict; file, traversal, aggregate, archive expansion and metadata work have quotas. HTTP selection stays under server-authorized SOURCES/TENANT/REPOSITORY. | SafeSourceReader, ContentAddressedStore, HTTP source-binding and symlink regressions; malformed ZIP EOCD/central-directory bounds. Parent-directory replacement by a malicious local administrator is outside the model. |
| Snapshot replacement | Partial input preserves unmentioned documents. Complete input must explicitly delete every absent document in that repository. Unrelated repositories retain identity and revision. | GenerationBuilder merge and fullSnapshot metadata; deletion/partial tests and reindex revision regression. |
| Authoritative recovery | Immutable manifest, CAS digests and committed index metadata determine content. Progress checkpoints are validated hints and never authorize skipping source records. | CheckpointStore bounds/checksum; GenerationBuilder validates hint then rebuilds from authoritative records; resume after original input deletion. |
| Durable publication | A visible generation is a committed, warmed, checksum/count/content/snapshot-verified reader. CURRENT changes through same-filesystem atomic rename after file/directory sync. | GenerationBuilder, GenerationPublisher;100 seeded failure schedules and corrupt-current fallback tests. Filesystem must support these primitives; power-loss hardware behavior is not inferred from exception injection. |
| Live reader lifetime | One request leases exactly one committed reader for candidates/count/facets/snippets/explanations/cursors. Publication retires old acquisition, while existing leases remain valid until close. | GenerationLease reference counts; old/new lease tests, paused-writer availability regression, post-pointer-failure retirement/refcount/pruning tests. |
| File lifetime | CURRENT/PREVIOUS generation files remain available for recovery; leased older files remain until last close. Other committed files may be pruned. CAS/job history requires separate operator retention. | GenerationPublisher publish/release/startup cleanup. Close rejects outstanding leases; no distributed reader ownership is claimed. |
| Tenant/repository authorization | Permission predicates precede retrieval, counts, facets, suggestions, snippets and explanations. Cache context includes permissions/version/generation/query/page, with a version recheck before return. | AuthorizationFilter and SearchEngine; real populated foreign-tenant/denied-repository fixtures and warmed-cache revocation tests. A permission update after the final recheck is a later policy event. Raw Lucene collection statistics are omitted from explanations; tenant-reader BM25 scores/order retain statistical coupling across repositories, explicitly documented in SECURITY. |
| Cursor continuity | Signed cursor binds principal/tenant/permission version/query digest/generation/offset/expiry. A retired requested generation returns410; a cursor never pins a reader indefinitely. | SearchCursor authenticated encoding/decoding and tamper/context/expiry/retirement tests. |
| Bounded query work | Input<=512 UTF16 characters,64 lexical tokens,depth8,page<=100,candidates<=500,suggestions<=20,cache<=128 responses,stored explanation<=4096 characters, complete query plan<=768 terms. Optional coverage uses<=64 distinct query terms and only authorized document term vectors; explicit query syntax disables it. | QueryAst, Request, CandidateRetriever, SearchEngine and explanation/cache regression. Exact counts may scan more matches than the candidate window. |
| Bounded adapters | Raw HTTP body<=65536 bytes before conversion;32 admitted requests;2 build workers and8 queued jobs. Ingestion/resume/reindex share admission. Data directory has one application owner. | AdmissionFilter, SearchController, DataDirectoryLock; oversized raw-body wire test and data-lock/recovery tests. Source acquisition precedes queued index building and remains within request/input quotas. |
| Token authenticity | RS256 crypto/issuer/time checks precede raw signed JSON claim-type checks. Subject/tenant/audience/expiry/search scope are required; repository permissions come from server mapping. | SecurityConfiguration and actual live-JWKS HTTP negatives, including signed numeric/array/null/blank subjects. CLI uses trusted local filesystem administration. |
| Evaluation independence | Frozen80 graded queries and40/20/20 split cannot be relabeled based on scores. Selection binds model bytecode and frozen data before held-out execution. | V1/V2 history, v3 pre-measurement coordinator approval, FREEZE.sha256, selection.txt, HELDOUT-OPENED.txt. Current real held-out metrics remain unmeasured; preliminary failures are preserved. |

STATUS records which source checkpoint actually executed each regression. Newly authored invariants are not treated as passed until that invocation completes. ENOSPC integration uses a real `/dev/full` kernel failure at the pointer boundary; it does not claim the actual index filesystem was filled.
