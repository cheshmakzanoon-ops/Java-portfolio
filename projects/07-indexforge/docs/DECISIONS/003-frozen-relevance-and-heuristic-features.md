# ADR003: freeze judgments and identify the executable model before evaluation

Status: protocol implemented; relevance acceptance remains FAILED. Held-out queries have never been searched or measured.

The quality claim requires graded queries whose labels exist before model measurements. The first templated smoke corpus was rejected by independent review and retained as smoke evidence. A substantive70-document authored-source corpus with provenance and near-domain distractors replaced it; a second review removed unsupported secondary labels before any measurement. Approved V3 contains80 queries split40 development/20 validation/20 held-out. Corpus/judgment hashes, correction reasons, prior versions and independent review are preserved. Unjudged documents contribute zero pooled gain under the declared metric policy, not a claim of universal irrelevance. This authored corpus is not an external benchmark.

Feature and parameter rounds preregister bounded candidates before their scores: field-weight/coverage presets, conventional BM25 k1/b presets, and generic JDK/Lucene API-topic hints. Validation selection requires no nDCG or identifier-MRR regression against baseline, then maximizes the weaker normalized nDCG/.75 and identifierMRR/.90 target with fixed ties. Development/validation have been reused across rounds; their improvement is selection evidence and may overfit. Only a frozen final choice can precede the held-out comparison. A global fixture-level seal plus an output-local seal prevent changed-model held-out reuse through fresh output/data directories. Model identity includes original class bytes, indexing helpers, full packaged shaded artifact/dependencies and ranking profile.

We rejected answer tables, project/document priors and relabeling after results. BM25, English stopwords and Porter stemming are reused Lucene algorithms; original identifier analysis, bounded parsing/planning, source features and evaluation orchestration are distinguished from them. Generic code-topic patterns use a bounded lexer that ignores comments/literals and abstains on locally shadowed API names. They are lexical associations, not type resolution or proof of security, durability or working behavior. External shadowing, cross-receiver associations and incomplete source remain limitations. Explicit Boolean/phrase/field and single-identifier semantics disable the hint query; NO_CODE_FEATURES and near-topic/comment/string controls remain published.

The fixed four-profile hint grid selects CODE_HIGH/SOURCE_AWARE: development nDCG10=.6802153485, validation nDCG10=.5804173420, validation identifierMRR10=.7833333333. The zero-weight control reproduces the earlier .5532469485/.7833333333 result. One validation prose query worsened; all per-query rankings and ablations remain. Generic identifier ambiguity is unresolved, and mandatory .75/.90 targets are unmet. No held-out score or final candidate adoption is claimed.

Certification23 changed only bounded analyzer EOF and cursor length test oracles. Its entire CLI artifact is byte-identical to evaluated22, so the selected model identity is unchanged; the exact source/test and artifact identity envelope records this rather than silently reusing stale metrics. Subsequent production/dependency/artifact changes require a new identity and applicable verification. Performance preparation is explicitly unmeasured and cannot substitute for relevance or quiet-reference results.
