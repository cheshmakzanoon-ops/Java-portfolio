# ADR003: freeze judgments and executable identity before evaluation

Status: the first frozen final evaluation failed P07-A4; baseline remains selected.

A relevance claim requires graded queries whose labels precede model measurements. The first templated smoke corpus was rejected before measurement and retained as smoke evidence. A substantive 70-document authored-source corpus with provenance and near-domain distractors replaced it. Review removed unsupported secondary labels before freezing V3: 80 queries split 40 development, 20 validation and20 held-out. Corpus/judgment hashes, correction reasons and earlier versions remain preserved. Unjudged documents contribute zero pooled gain under the declared metric policy; this does not establish universal irrelevance. The authored corpus is not an external benchmark.

Feature rounds registered bounded candidates before measurement: field-weight/coverage presets, conventional BM25 k1/b presets and generic JDK/Lucene API-topic hints. Validation selection required no nDCG or identifier-MRR regression against baseline, then maximized the weaker normalized target, nDCG/ 0.75 or identifier-MRR/ 0.90, with fixed ties. Repeated development/validation use can overfit. A global fixture-level seal and output-local seal bind the frozen decision and executable identity before final query/grade interpretation and execution. Changing the output directory cannot silently open a different model.

The implementation excludes answer tables, project/document priors and post-result relabeling. Lucene supplies BM25, English stopwords and Porter stemming. Original bounded parsing/planning, identifier analysis and source features remain separate from those reused algorithms. Generic topic patterns ignore comments/literals and abstain on locally shadowed API names; they are lexical associations rather than type resolution or proof of runtime behavior. External shadowing, cross-receiver association and incomplete source are limitations. Explicit Boolean/phrase/field queries and bare identifiers bypass that hint lane; ablation and distractor controls remain in the evidence.

The fixed four-profile grid selected CODE_HIGH/SOURCE_AWARE with development nDCG@10 of 0.6802153485, validation nDCG@10 of 0.5804173420 and validation identifier MRR@10 of 0.7833333333. The zero-weight control reproduced 0.5532469485 / 0.7833333333. One validation prose query worsened. Identifier ambiguity remained unresolved and the declared targets remained unmet.

Certification23 changed test oracles for analyzer EOF and cursor length; its CLI bytes matched evaluated22. Corrected24 changed unambiguous request-context encoding and its regression, then exactly replayed all 540 development/validation metric/path rows under a new artifact identity. The first final comparison produced baseline 0.6012721858 nDCG / 0.8833333333 identifier-MRR and candidate 0.6267961004 / 0.8000000000. Both missed 0.75 / 0.90; the frozen guard retained baseline because identifier-MRR regressed. All nine modes, per-query failures and seals remain preserved. No held-out-winning ablation replaced the selected model, and compiled defaults were not changed after results.

The historical reference used BASELINE/CODE_HIGH, where baseline bypasses feature weights and retains content BM25. Future source/dependency changes require a new executable identity and applicable correctness verification. New experiments require a separately declared protocol that preserves earlier seals/results and discloses repeated-test exposure. Correctness verification does not refresh historical relevance or performance measurements.
