# Engineering walkthrough

Start with `scripts/up.sh` and the CLI demo. Up prepares project-owned local data; demo creates a separate seeded run and asserts identifier/prose retrieval, explicit deletion under search load, denied-repository isolation, interrupted build and restart.20k is the default and2k is the CI setting. Check STATUS for the exact sizes already observed; the advertised command is not a measurement claim.

Trace an ingestion through SafeSourceReader → ContentAddressedStore → SnapshotManifest → IngestionJob. Explain strict UTF8, canonical relative paths, symlink/parent escape, bounded streaming directory traversal, bounded ZIP container/expansion checks, deterministic bytes, and retry conflicts. Show why an immutable manifest lets resume work after the original source file disappears. A checkpoint cannot replace source authority.

Trace GenerationBuilder → GenerationPublisher → GenerationLease. Lucene provides indexing/BM25/segments/commits; original application code builds a complete replacement, validates source metadata and hashes, warms the committed reader, forces metadata, and atomically publishes a checksummed pointer. CURRENT/PREVIOUS recovery and quarantine are local filesystem assumptions. Show the100 seeded failure schedule CSV without calling it100 real power cuts. Demonstrate why request leases keep old data valid after publication and why file cleanup waits for the last lease.

Walk through the concurrency bug recorded in the case study. Holding the engine monitor throughout a replacement prevented new requests from acquiring the old committed generation. The fix uses per-tenant writer locks and a short publisher-map critical section; a latch-held build test proves old search returns before release. Publication itself still holds the publisher lock while verifying the next generation, so new acquisitions can pause during that verification. Existing acquired leases continue. This is a practical limit, not a claim of lock-free search.

Trace a search through QueryAst → QueryPlanner → AuthorizationFilter → CandidateRetriever → Ranker → snippet/explanation → authorization recheck. Explain OR adjacency, AND precedence, phrase/field bounds and unsupported wildcard/regex/fuzzy forms. The original identifier analyzer preserves source offsets/full identifiers and emits acronym/camel/underscore parts at synonym positions. The declaration hint scanner is conservative lexical analysis, not Java compilation. Distinguish exact metadata from analyzed prose; show baseline, source-aware weights, stable key tie-breaking and feature ablations.

Explain why filtering only final hits is insufficient: inaccessible content could affect candidates, counts, facets, suggestions and explanations. Show populated denied/foreign fixtures and warmed cache revocation. Cursors bind the policy version and generation; retiring old cursor access avoids indefinite retention. The final version recheck defines the response policy snapshot; no constant-time confidentiality on shared hardware is claimed.

Trace an HTTP JWT through live JWKS signature verification, issuer/time validation, original signed JSON type checks and server-side identity mapping. Nimbus can coerce a numeric subject into a string, so decoded-string checks alone were insufficient. Show the actual signed numeric/array/null/blank subject regressions. Discuss bounded raw bodies and request/job admission, generic errors, protected configuration, and why CLI remains local administrative access.

Review the evaluation history candidly. Independent review rejected the initial toy corpus before scores. Substantive source/provenance/distractors replaced it;16 unsupported secondary labels were corrected before any measurement. The frozen80-query v3 and coordinator approval remain intact. Preliminary source-aware ranking improves nDCG modestly while validation reciprocal rank regresses; generic identifier intents and paraphrased prose are genuine failures. Held-out remains unmeasured until the model is selected. Do not claim the quality gate from the preliminary numbers.

Discuss performance using raw reference-run output rather than estimated throughput. The harness offers30 requests/second including scheduled-arrival queuing, warms150 requests, runs three measurements, fixes the heap at2GiB, and records exact corpus bytes, latency/errors/GC/CPU/allocation/queue peak. Its boundary is shared application search and excludes HTTP transport. A quiet coordinator window and source/environment fingerprint are prerequisites; STATUS identifies any pending gate.

Close the walkthrough with tradeoffs a reviewer can test: full replacement costs disk/work; a500-candidate window bounds reranking but limits pagination depth; conservative Java declaration hints can miss syntax; lexical search does not understand every paraphrase; CAS/job retention is manual; local directory force/atomic rename do not prove arbitrary storage durability. The owned work is the application lifecycle, boundaries and algorithms, not Lucene's inverted index.
