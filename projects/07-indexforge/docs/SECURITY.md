# Security boundary

Only explicitly configured local roots are read. HTTP inputs are confined to `SOURCES/TENANT/REPOSITORY`, using server-authenticated tenant/repository permissions before opening input; binding symlinks and parent escape are rejected. Source/document UTF8 and bounded ZIP members are data; no builds, archive classes or network crawlers execute. No third-party fixture license is needed: authored examples and frozen original code from this Apache-2.0-licensed repository retain provenance paths/digests in fixtures/corpus.jsonl. Zip member names cannot escape and archive data is never extracted. Bounded ZIP container validation checks EOCD/central-header bounds and declared/local entry-count agreement before accepting a snapshot. ZIP64 and spanned archives are explicitly unsupported; the supported ordinary ZIP format permits at most65534 entries even when a larger general snapshot quota is configured.

Remote HTTP identities use real RS256 JWT signature validation through JWKS and issuer validation. Required subject, audience indexforge, expiry, typed tenant and search scope are checked explicitly. Original signed JSON claim types are validated after normal cryptographic/issuer/time decoding because Nimbus can coerce numeric subjects into strings. Write requests also require ingest scope. The server maps subjects to tenant/repository permissions and administrator status; a mismatching token tenant is forbidden. The protected profile requires explicit issuer/JWKS/users configuration. Development is a clearly named disposable issuer bound to loopback; it cannot bind externally.

Authorization is applied before candidate selection, exact hit counts, repository facets, snippets, ranking explanations, suggestions and application-cache reads. Tenant index directories are separate. Results are discarded/retried if the server permission version changes before completion. Signed cursors bind tenant/principal/version/query/generation/expiry; a transferred/tampered/expired cursor fails. Retired generations return410. Cache keys include the complete access context and generation.

Raw bodies are bounded before JSON conversion; admitted requests and ingestion queues are bounded. Query parser rejects wildcard/regex/fuzzy constructs and excessive clauses/depth. Exceptions returned to clients contain stable generic codes rather than inaccessible names. Plain source snippets and explanation strings require text rendering by clients. Local CLI is administrative filesystem-trusted access and does not pretend to authenticate an untrusted local OS user.

Excluded guarantees: constant-time confidentiality on shared CPUs, protection from an attacker who can modify server data or replace source-root directory ancestors concurrently, distributed filesystem durability, credential theft by the same OS account, or universal search quality beyond the published corpus. No production deployment/security certification is claimed.

User-facing explanations export only matching features of an authorized document, its numeric score and explicit reranking bonuses. Raw Lucene explanations are never returned: their n/N/avgdl/document-frequency statistics include the tenant reader's inaccessible repositories. Denied-repository tests exercise fresh and warmed responses, facets, snippets, suggestions and permission revocation. Lucene BM25 still uses tenant-reader collection statistics internally, so numeric scores and result order can depend on documents in other repositories in the same tenant. This is a statistical confidentiality limitation distinct from timing; ACL statistical noninterference is not claimed. Tenant indexes are physically separate.

Committed generations record the immutable job ID and manifest digest. Startup and every subsequent tenant writer reconcile the current committed identity into an atomic checksummed completion receipt before another generation can replace it. Receipts bind schema, job ID, manifest digest and generation UUID; malformed/truncated/oversized receipts fail explicitly. A publication whose atomic pointer rename succeeded before directory fsync failed is reconciled from the actual pointer; an unreadable ambiguous pointer blocks subsequent writes until restart recovery.
