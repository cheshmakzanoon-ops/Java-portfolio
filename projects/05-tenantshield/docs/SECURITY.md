# Security model

Only a fixed configured issuer/JWKS URI, expected audience `tenantshield`, and RS256 are accepted. Expiry and issued-at are required; future issued-at, future not-before and expired tokens are rejected with zero clock leeway in the baseline. No issuer discovery URL is derived from unverified claims. The fixture uses a genuine Keycloak password grant solely for disposable local demonstration. Applications do not implement passwords or cryptography. Nimbus/Spring verify signatures. Synthetic signing in JwtSecurityTest is adversarial test fixture generation using Nimbus.

The route tenant is bound to an active database membership for `(issuer,subject)`. JWT role strings and caller headers never confer permissions. Administrative access uses a separate server-side administrative flag checked in a fresh transaction. Request bodies cannot specify a subject, department, clearance, suspension or classification. The application mapper rejects duplicate JSON keys, trailing documents, unknown fields, lossy integer conversion and numeric enum values. Context only accepts purpose (bounded string) and hour (int64); unknown JSON properties and context keys fail.

The policy language has no reflection, imports, regex operators, dynamic evaluation, loops, network or arbitrary function calls. Parser/compiler reject unknown names and invalid types. Strings, AST size, nesting, literal sets, roles and grants have hard bounds. HTTP bodies are read through a 262145-byte sentinel before Jackson, including requests without Content-Length; this caps bytes before deserialization. 64 concurrent decision requests, 128 connections, bounded accept queue, per-tenant 5000 requests/second fixed-window limits and 1000 quota buckets bound capacity. Fixed windows permit a boundary burst of up to twice the nominal one-second quota. Protected document server has 32 threads/connections bounded at 64 and a 5-second authorization read timeout.

Database runtime credentials use a separate non-owner, non-BYPASSRLS role. Composite tenant keys/FKs and RLS enforce scope. Transaction-local settings clear on rollback/commit before a connection returns to Hikari. RLS does not defend against untrusted users with raw runtime SQL access. Applications use prepared SQL; no tenant string is interpolated into SQL. PostgreSQL/Flyway migration privileges stay outside the running services.

Audit contains random decision ID, SHA-256 principal reference `(issuer,NUL,subject)`, action, resource ID, epoch, result and reason. No token or complete attribute set is persisted in audit or printed. Principal hashes are pseudonymous, not anonymous; action/resource identifiers remain visible to current tenant administrators. Audit failure prevents ALLOW responses. Tenant audit reads cap at 100 entries. Metrics are current-admin gated and scoped by tenant.

Committed passwords are explicitly disposable loopback fixtures, not production secrets. All published Compose ports and HTTP service bindings default to 127.0.0.1. Keycloak bootstrap administrator is fixture-only. Production deployment, TLS termination, secret management, retention/erasure policy, principal pseudonym keying, cross-datacenter consistency and certifications are outside this demonstration. See the repository SECURITY.md for reporting.

Nonmembers receive no policy/resource version metadata and no resource resolution is performed for them. A revoked, retained membership can observe its tenant epoch for explicit revocation evidence, but still receives no resource metadata. Tenant existence itself is not secret in this fictional SaaS; there is no cross-tenant data endpoint.

Quota route segments are decoded and validated before forming cache keys, so encoded spellings cannot multiply a tenant's quota. Caller purpose/hour remain untrusted request annotations; `hour` is not trusted server time. Security schedules require a server-owned clock attribute rather than trusting that annotation. Resource versions advance automatically on maintenance updates together with tenant authorization epoch; active policy pointers reject non-increasing updates in PostgreSQL. The runtime role cannot update/delete audit rows or create/delete tenants.

Original signed claim types are checked after Spring/Nimbus successfully verifies cryptography and trust. Some Nimbus paths coerce a numeric JSON subject into a Java string before claim conversion, so inspecting only `Jwt.getSubject()` is insufficient. Both service decoders parse the original compact-JWS payload with duplicate detection and explicit JSON size/depth/token limits, require a nonblank original string subject of at most 128 characters, and compare it to the verified identity. Tokens over 16KiB are rejected before decoding. This is additional claim-shape validation, not a replacement signature implementation. Token tenant claims remain irrelevant to membership binding.

Policy publication and rollback accept exactly one strong quoted nonnegative int64 version in `If-Match`. Weak tags, lists, wildcards, inserted quotes, leading signs or zeroes, and overflow return 400 before database access. A valid stale version returns 409. This precondition is a concurrency control; current tenant administrative membership remains independently required.
