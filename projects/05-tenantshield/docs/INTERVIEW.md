# Technical walkthrough (10–15 minutes)

Use the tested commands and current limitations in [STATUS](STATUS.md). The runnable short demonstration is `projects/05-tenantshield/scripts/demo.sh` after `up.sh`; do not describe an unexecuted demo or pending measurement as evidence.

1. **Trace one protected operation (two minutes).** Start in `ProtectedDocuments.read`, which forwards the validated bearer to a fresh authorization request. Follow `DecisionController.decide` into `PolicyStore.decide`: one repeatable-read transaction establishes tenant context and reads epoch, current `(issuer,subject)` membership, immutable active revision and server-owned resource attributes. Explain why caller context cannot supply clearance or classification. Audit must commit before returning ALLOW.
2. **State the invariant (two minutes).** A snapshot established after a successful membership-revocation commit cannot allow through a stale AST cache. The cache stores immutable compiled content under `(tenant,version,digest)` and never caches a permission result. Point to `pooledTenantIsolationImmutableRevisionsAndSnapshotRevocationBoundary`, including its deliberately paused older snapshot and new post-commit requests. Explain the weaker guarantee for an already established snapshot and the gap between a remote authorization response and a later resource write.
3. **Read the original compiler (two minutes).** Walk tokenizer → recursive descent → statically typed sealed AST → role DAG closure → action/type candidate index. Demonstrate `not UNKNOWN == UNKNOWN`; explicit TRUE deny wins, then any applicable unknown/error denies, then both grant and allow are required. Explain `editor -> reader` inheritance direction. Show byte/node/depth/literal/evaluation bounds and deterministic rule ordering.
4. **Explain hostile input and trust (two minutes).** Signature, fixed issuer/JWKS, RS256, audience and required times are checked by Spring/Nimbus. The original signed payload subject is then checked as a bounded nonblank JSON string because a library may coerce numeric claims before exposing them. A tenant claim grants nothing; the route tenant needs current server-side membership. Point to correctly signed negative fixtures and the real Keycloak integration suite, keeping unit decoder evidence separate from complete HTTP proof. Explain why RLS is useful against omitted predicates yet does not protect against someone holding raw runtime SQL credentials.
5. **Explain the worst dependency failure (two minutes).** Pause PostgreSQL or revoke audit INSERT in the integration test. Authorization returns an explicit error, and the protected document API refuses the operation. Distinguish a dependency failure from a normal DENY; no stale ALLOW fallback exists. Publication is SERIALIZABLE with an expected active version. Rollback copies old contents into a higher immutable revision and publishes within the same mutation transaction.
6. **Read measurements and a defensible tradeoff (two minutes).** Open actual completed evidence when available; otherwise state the measurement gate is still pending. Separate cold compilation, warm indexed evaluation and authenticated HTTP including persisted audit. Read p50/p95/p99 together with errors, denials, SQL count, cache size, concurrency, pool size and the server JFR summary. Discuss coordinated omission and sampled allocation limits. The next likely scaling cost is the per-decision database/audit boundary, not a reason to silently add stale decision caching.

A small live change: add a bounded approved context field with a static type, update the contract and normalization, write a malformed-type and UNKNOWN case, then run unit tests. Do not add a dynamic expression engine or accept caller-owned subject attributes to make the demonstration easier.

# Provenance

This project was implemented with AI coding assistance as part of the repository's coordinated portfolio execution. The parser, compiler, combining algorithm, reference interpreter, tenant transaction code and workload are project implementations. Spring Security/Nimbus provide JWT cryptography and token validation; Keycloak provides identity issuance; PostgreSQL provides isolation/RLS; Flyway, HikariCP, Caffeine, Testcontainers, JUnit, AssertJ, ArchUnit and JMH supply supporting mechanisms. Dependency versions are inherited from the repository parent. Fixtures use fictional tenants, users and documents and disposable local credentials. No production customer data, commercial incident history, employment tenure or security certification is claimed.
