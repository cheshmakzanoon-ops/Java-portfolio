# Engineering case study

ThreadLens distinguishes three common causes of slowdown: more computation, more allocation and more waiting. JFR samples, weighted allocation events, monitor durations and selected-method timings answer different questions. Their units, intervals and loss must remain visible for the reports to support a sound diagnosis.

Observation ownership is the central implementation concern. A producer can reserve a ring slot just before shutdown, a consumer can fail after reclaiming an event, and another startup declaration can replace a process-global sink. ThreadLens now establishes the writer, consumer, transformer and shutdown owner before enabling probes; one premain attempt owns that sink. Shutdown closes admission, accounts accepted reservations and exposes unfinished work instead of reading mutable statistics after a timed-out join. Independent JVMs preserve application results while testing saturation, duplicate startup and a paused exit during System.exit.

The live event path needs the same discipline. Its extracted EventProcessor owns queue admission, every accumulator mutation and bounded drain. Callback-triggered close must return before its own consumer can terminate; holding a lifecycle lock while another thread joins would prevent that return. Deterministic schedules now cover that ordering, explicit deadlines, blocked observers and cleanup retries. Filesystem budgets likewise require a real boundary: lexical path normalization can conceal symlink traversal, and a depth-limited walk cannot treat an unvisited subtree as empty.

Bounded aggregation also has semantic consequences. A full stack trie must not suppress a known hotspot later in the same sample. Method totals and trie insertion therefore run independently, while overflow remains explicit. Published profiles freeze sorted maps, and reports validate denominators, coordinates and quantiles before presenting imported measurements. Native offline navigation keeps hostile identifiers as literal text and contains wide tables within their own scroll regions.

The historical implementation encountered two useful failures. Per-invocation TSV output reached its 256-MiB budget after 42 measured allocation seconds plus three warmup seconds. The host finished, but that collector could not complete a 90-second instrumented trial. Bounded HDR summaries and a 10,000-row raw prefix replaced output proportional to invocation volume; omitted prefix rows remain distinct from lost histogram observations.

The first complete 84-JVM overhead study then failed several prescribed medians. Subsequent historical settings passed seven paired cause trials per cause and a 1,202.669-second stress run with explicit event loss/incomplete windows. Those outcomes and the failed study remain preserved. New ownership checks and correctness tests do not establish a measured speedup: the complete overhead remeasurement remains open.
