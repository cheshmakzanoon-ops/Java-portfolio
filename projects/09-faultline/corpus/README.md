# Preregistered corpus

The required corpus has 120 Java sources: 60 modeled positives and 60 closely matched negatives, 20 pairs in each of SQL text, shell command string, and filesystem access path. Shapes cover direct flow, branches, loops, switch expressions, overloads, interface inheritance, recursion, exceptions, category-two arithmetic, string concatenation, lambdas, collections, fields, arrays, builders, wrong-context sanitizer appearances, safe binding/no-shell argv/normalization, missing dependencies, missing debug tables, and casts.

`labels/frozen-v1.json` and `SHA256SUMS-v1` preserve initial preregistration; exact original sources are in `archive/frozen-v1/src`. Semantic review took place before engine evaluation and required supplied SQL receivers, a fixed shell executable prefix, and confinement checks on the final transformed path. `labels/frozen-v2.json` and `SHA256SUMS-v2` freeze those reviewed sources. The approved v2 label-file SHA-256 was `d82a27da446265ee38a30f39265c2e71e93b4023a99849db621f0039483443da` before first corpus metrics. The engine may be corrected; labels must not be tuned to outcomes.

`CorpusTest` recompiles owned sources with `-proc:none`, compiles shape19 with `-g:none`, removes the explicitly modeled missing dependency, checks every frozen source hash, scans actual classfiles and publishes every result row plus per-rule TP/TN/FP/FN in `evaluation/target/corpus-results.json`. Unsupported adversarial fixtures are separate boundary tests and do not inflate the matrix. Required gates are all60 positives and at least57 negatives; these are corpus results, not estimates of field accuracy.

Fixtures are never executed. SQL Statement/Connection receivers are supplied arguments with a non-null caller precondition. Shell negative fixtures use an allowlisted token after fixed `/bin/echo`; argv without a shell is a separate negative. Path negatives validate their final path under the lexical, owned-root assumption documented in the threat model. Label rationales disclose uncertainty and limited context assumptions.

## Extension corpus for model 1.1.0

`extension-v1/` holds 38 fixtures for the rules and sources added in model 1.1.0: 32 per-rule fixtures (16 positives and 16 negatives, four of each for `BG-CLASS-LOAD`, `BG-URL-FETCH`, `BG-XPATH-QUERY` and `BG-LDAP-FILTER`) and six that start from servlet requests (four positives, two negatives). The positives vary the shape (direct, branch, concatenation or builder, interprocedural, and every overload family that has a fixture); the negatives are sanitized, constant, external value in a *different* argument (the LDAP search base, the XPath context item, the `Socket` port: the precision controls) or overwritten before the sink. `labels/extension-v1.json` pins every source, the trusted `SafeExtension` helper and the servlet stubs by SHA-256; `ExtensionCorpusTest` checks the hashes, recompiles with `-proc:none`, scans the classfiles with the built-in model and requires every fixture to be classified as labelled, with no finding under another rule. Labels were written from the intended pattern before the first run and are never adjusted to fit a result. The fixtures were all classified correctly on first evaluation, which says the modeled patterns work, not how the analyzer performs on real code.

The frozen v2 corpus above is untouched; the two corpora are compiled and scanned separately. `BuiltInSinkCoverageTest` complements them by generating one class per built-in sink descriptor (29), resolving each reflectively against the running JDK so a mistyped descriptor cannot pass, and requiring a finding under the sink's own rule.

## Byte immutability across project renames

Both frozen label sets pin SHA-256 hashes of the fixture bytes, including `archive/frozen-v1/src`. Fixtures read `System.getenv("BYTEGUARD_INPUT")` because that was the project's name when they were frozen; the literal is inert (the analyzer models `System.getenv(String)` by descriptor and fixtures are never executed) but it is part of the hashed bytes. The October 2026 project rename rewrote it to `FAULTLINE_INPUT` in all 240 files, which made `CorpusTest.frozenLabelsMatchEveryResultAndThresholds` fail at its first hash check. The original bytes were restored and re-verified against `frozen-v1.json` and `frozen-v2.json` (0 mismatches across 240 files). Any future text rewrite must exclude `corpus/src` and `corpus/archive`; a legitimate fixture change requires a new, versioned freeze, never an edit in place.
