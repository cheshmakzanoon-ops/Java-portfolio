# Threat model and unsupported inventory

The analyzer reads untrusted local bytes selected by the caller. It must not execute classes, initialize static fields, extract archives, resolve target dependencies over the network, or run annotation processors. Trusted corpus compilation is a separate evaluation operation with `-proc:none`; only committed owned sources are compiled.

Default input bounds are 25,000 entries, 200 MiB total actual expanded bytes, 8 MiB per entry/class, expansion ratio 100, no nested archive, and 120 seconds. Symbolic links and ambiguous duplicate classes are rejected. Archive entry names are limited to4096 characters; deeply malformed annotation structures fail without executing target code. Unused annotations, arbitrary attributes and source-debug blobs are not retained. The CLI writes only the explicit output path and local owned demo/benchmark files when those scripts are invoked. No target archive paths become output paths.

Default analysis bounds are 50,000,000 charged work operations, 120 seconds, 32 dispatch targets, five traced call-provenance steps, and one caller instruction as the summary instantiation context. Additional fixed parser/state-allocation limits are 2,000,000 visitor facts (charged before ASM tree allocation), 8,000,000 frame cells,4096 taint identities/references per value, and10,000 distinct diagnostics; exceeding these produces explicit partial coverage. Frame-cell charging is cumulative allocation work, conservatively bounding retained frame state. Heap approximation is field-sensitive/object-insensitive with conservative array contents. A dispatch or unsupported-bootstrap coverage limit is partial; an unknown library is a conservative transfer with an explicit diagnostic. Neither is a deliberate suppression. Only exact finding fingerprints enter baseline comparison.

Unsupported behavior, kept outside the confusion matrix: implicit information flow through branches; arbitrary reflection/dynamic loading; native implementations; arbitrary bootstrap methods; effect-sensitive exception types and class initialization ordering; full object-sensitive alias analysis; path symlink races; complete JVM verification; legacy jsr/ret subroutines. Unknown behavior must not be interpreted as a clean value. Unsupported `invokedynamic` receives unknown-taint transfer and an explicit partial frontier, including void-returning sites.

Sanitizer declarations are trusted model assumptions, not discovered proofs. The fixture SQL identifier validator demonstrates a restricted SQL-token context, not safety for arbitrary query grammar. Shell token validation is used after a fixed `/bin/echo ` command. `Safe.confinedPath` is lexical final-path validation under an owned, symlink-free `/sandbox` fixture root; it is not a production filesystem-confinement primitive. Normalization alone and sanitizer-like names are not sanitizers.

The supported synthetic corpus labels model flows, not confirmed vulnerabilities. For example SQL16's wrong-context shell whitelist can overlap SQL-safe characters but remains a positive for the intentionally context-specific model. A missing dependency can legitimately reduce confidence or cause a false positive. Report unknown counts and every label/result row rather than relabeling away uncertainty.

Heap reference aliases have a separate precision boundary from one-callsite taint-summary instances. Field, mutable return, and formal-parameter identities weakly merge references across calls. The same `pass(String[])` helper used by a source-filled array and a constant-only array therefore contaminates the clean call in the flow-insensitive heap. A retained bounded analyzer control observed findings in both `tainted` and `clean` sink methods; the clean result is an acknowledged false positive. Its original capture locations were `.work/A09/preflight-fixtures/ReusedAlias` and `.work/A09/reused-helper-control.log`; these ignored measurement-machine artifacts are not supplied by a Git clone. This control is outside the frozen 120-row model corpus and is not relabeled or counted as a passing negative. Distinct callsite summary keys do not imply context-sensitive heap aliases. Alias closure is iterative, charges the shared budget, and stops at4096 identities per value; retained alias edges also spend the structural-fact budget.

Supported lambda summary composition is bounded to known static/synthetic implementation handles. Their dependencies enter the call graph so caller evaluation is repeated when implementation summaries grow, including under reverse scheduling. Unresolved implementation handles, virtual/constructor dispatch and mutable heap/return effects are explicitly partial rather than treated as a clean supported lambda. Unknown/native mutation of a passed object is consumed by scalar field reads as well as array/collection element reads; arbitrary unpassed globals remain outside operand-based conservative transfer.
